## Часть 1 — Подключаемся из кода (10 мин)

### Что такое Mongoose

**Mongoose** — библиотека, через которую Node.js разговаривает с MongoDB.

**Сравнение:** `axios` помогает делать запросы к чужому API. `mongoose` помогает делать
запросы к своей базе.

### Код

Откройте `steps/1-connect.js`:

```js
import 'dotenv/config'
import mongoose from 'mongoose'

try {
  await mongoose.connect(process.env.MONGODB_URI, { serverSelectionTimeoutMS: 5000 })
  console.log('✅ MongoDB подключена, база:', mongoose.connection.name)
} catch (error) {
  console.log('❌ Не удалось подключиться:', error.message)
}

await mongoose.disconnect()
```

**Здесь:**

- `import 'dotenv/config'` — читает файл `.env` и кладёт всё из него в `process.env`.
  Одна строка, никаких вызовов — импорт сам всё делает.
- `process.env.MONGODB_URI` — имя после `process.env.` совпадает с именем в `.env`.
  Переименуете там — сломается здесь.
- `await mongoose.connect(...)` — подключение идёт через интернет, поэтому `await`.
- `serverSelectionTimeoutMS: 5000` — ждать базу не дольше 5 секунд. Без этой настройки
  при ошибке вы бы сидели перед чёрным экраном 30 секунд и думали, что всё зависло.
- `try / catch` — то же, что вы писали вокруг `fetch` в React. Без него ошибка
  подключения вывалится страшной простынёй на пол-экрана.
- `mongoose.disconnect()` — отпускаем соединение, иначе программа не завершится.

### Запускаем

```bash
npm run step1
```

Ждём:

```text
✅ MongoDB подключена, база: tasks
```

```text
steps/1-connect.js
      ↓ читает
    .env  →  MONGODB_URI
      ↓ mongoose.connect
Atlas: Cluster0 → база tasks   ✅
```

### Если вместо ✅ ошибка — найдите свою строку

| Что в терминале | Что это значит | Что делать |
|---|---|---|
| `bad auth` / `Authentication failed` | неверный логин или пароль | пароль **пользователя базы** (п. 0.2.3), не от сайта. Скобки `< >` убрать |
| `must be a string, got "undefined"` | файл `.env` не прочитан | имя ровно `.env`, лежит рядом с `package.json`, внутри есть `MONGODB_URI=` |
| `querySrv ENOTFOUND` | адрес кластера с опечаткой | скопировать строку из Atlas заново |
| `Could not connect to any servers` / `Server selection timed out` | вашего IP нет в списке | Network Access → **ADD CURRENT IP ADDRESS** |
| `база: test` | в строке нет имени базы | дописать `/tasks` после `.mongodb.net` |

## Часть 2 — Задачи переезжают в базу (12 мин)

### Что такое модель

**Модель** — это объект, через который мы работаем с одной коллекцией. Из него берутся
все команды: найти, создать, удалить.

**Сравнение:** коллекция — это папка с документами в шкафу. Модель — сотрудник, который
единственный имеет к этой папке доступ. Вы не лезете в шкаф сами, вы просите его.

### Код

Откройте `steps/2-tasks.js`. Сравните с тем, что было на занятии 1: раньше задачи
лежали в массиве прямо в файле.

```js
// Модель: как выглядит одна задача
const Task = mongoose.model('Task', {
  title: String,
  isDone: Boolean,
})

app.get('/tasks', async (req, res) => {
  const tasks = await Task.find()
  res.json(tasks)
})

app.post('/tasks', async (req, res) => {
  const task = await Task.create({ title: req.body.title, isDone: false })
  res.status(201).json(task)
})
```

**Здесь:**

- `mongoose.model('Task', { … })` — два аргумента: **имя** модели и **описание полей**.
  По имени `'Task'` Mongoose сам найдёт коллекцию: переведёт во множественное число
  и в нижний регистр → **`tasks`**. Коллекцию создавать руками не надо, она появится
  при первой записи.
- `Task.find()` — **без аргументов значит «все»**. Вернётся массив.
- `Task.create({ … })` — создаёт и сразу сохраняет. Возвращает то, что записалось,
  уже с `_id`.
- `async` и `await` перед каждым обращением к базе — запрос уходит по сети, ответ
  приходит не мгновенно. Забудете `await` — получите `Promise` вместо данных.

Массив задач из файла **исчез**. Данные живут не в программе, а в базе.

### Запускаем и проверяем

```bash

```

Откройте `requests.http` (нужно расширение **REST Client**) и по очереди:

3. **«Все задачи»** → задача на месте.

## Часть 3 — 🔍 Поймай ошибку (5 мин)

Отправьте запрос с **опечаткой в названии поля**:

```http
POST http://localhost:3000/tasks
Content-Type: application/json

{ "titel": "Сделать домашку" }
```

Сервер отвечает **201 Created**. Посмотрите «Все задачи» и загляните в Atlas:

```json
{ "_id": "6aae4a...", "isDone": false, "__v": 0 }
```

**Задача без названия.** Сервер сказал «готово» и записал мусор.

> ❓ Вопрос классу: кто виноват — MongoDB, Mongoose или мы?

Мы. Посмотрите на модель:

```js
const Task = mongoose.model('Task', {
  title: String,
  isDone: Boolean,
})
```

Здесь написано только **какого типа** поля. Нигде не написано, что `title`
**обязателен**. Поэтому Mongoose рассуждает так:

- `titel` — такого поля в описании нет → **молча выбрасываю**;
- `title` — не прислали → пусто, и это не запрещено → **сохраняю**.

Программа сделала ровно то, что ей сказали. Мы не сказали правил.

Теперь представьте, что это не учебный список задач, а регистрация пользователей.
Опечатка на фронтенде — и в базе появляется человек без имени, без почты, без телефона.
Никто ничего не заметит, пока через месяц не начнут рассылать письма.

**Ставим охрану на вход.**

## Часть 4 — Schema: правила для данных (10 мин)

### Определение

**Schema (схема)** — описание того, как должен выглядеть документ: какие поля, какого
типа, какие **обязательны**, что подставить, если поле не прислали, и какие значения
вообще допустимы.

### Сравнение из жизни

Схема — это **бланк заявления** в банке.

| В бланке | В схеме |
|---|---|
| «Фамилия» — заполнить обязательно | `required: true` |
| «Отчество (при наличии)» | обычное поле, без `required` |
| «Гражданство: ☑ Узбекистан» — уже проставлено | `default: 'normal'` |
| «Пол: М / Ж» — только два варианта | `enum: ['low', 'normal', 'high']` |

Без бланка заявление можно подать на салфетке — его примут и потеряют. С бланком
сотрудник на входе скажет: «фамилию не заполнили, вот здесь».

### Код

Откройте `steps/3-schema.js`:

```js
const taskSchema = new mongoose.Schema({
  title: {
    type: String,
    required: [true, 'Поле title обязательно'],
  },
  isDone: {
    type: Boolean,
    default: false,
  },
  priority: {
    type: String,
    enum: {
      values: ['low', 'normal', 'high'],
      message: 'priority может быть только low, normal или high',
    },
    default: 'normal',
  },
})

const Task = mongoose.model('Task', taskSchema)
```

**Здесь:**

- `new mongoose.Schema({ … })` — схема стала **отдельной переменной**. Раньше объект
  с полями шёл прямо в `model()`. Так тоже можно, но правила удобнее держать отдельно:
  схему видно целиком, потом вынесем её в свой файл.
- `title: { type: String, … }` — вместо короткого `title: String` пишем объект.
  Как только у поля появляется хоть одно правило, короткая запись не годится:
  Mongoose должен понимать, где тип, а где правило.
- `required` — поля нет → документ **не сохранится**.
- `default` — поля нет → Mongoose подставит значение сам. Это **не то же самое**:
  `default` даёт запасной вариант, `required` запрещает отсутствие.
- `enum` — список допустимых значений, `"ochen srochno"` не пройдёт.
- `[true, 'текст']` и `{ values: […], message: 'текст' }` — длинная форма правила,
  где рядом лежит **своё сообщение об ошибке**. Форма разная, смысл один.

Изменилась ещё одна строка в `POST`:

```js
const task = await Task.create(req.body)
```

Раньше мы перечисляли поля руками: `{ title: req.body.title, isDone: false }`.
Теперь отдаём **всё тело запроса** — схема сама отбросит лишнее и подставит значения
по умолчанию. Меньше кода, и все правила в одном месте.

## Часть 5 — Понятный ответ об ошибке (8 мин)

Правила есть. Но что увидит тот, кто ошибся? Смотрим `POST` в `steps/3-schema.js`:

```js
app.post('/tasks', async (req, res) => {
  try {
    const task = await Task.create(req.body)
    res.status(201).json(task)
  } catch (error) {
    if (error.name === 'ValidationError') {
      const problems = Object.values(error.errors).map((item) => item.message)
      return res.status(400).json({ error: 'Задача не прошла проверку', problems })
    }
    res.status(500).json({ error: 'Ошибка сервера' })
  }
})
```

**Здесь:**

- `await Task.create()` теперь **может выбросить ошибку** — документ не прошёл правила.
  Без `try/catch` клиент получил бы `500` и простыню служебного текста.
- `error.name === 'ValidationError'` — **у ошибки есть имя**. Так Mongoose называет
  ошибки проверки. Это даёт нам отличить «клиент прислал ерунду» от «база отвалилась».
  Причины разные — и ответы должны быть разные.
- `error.errors` — объект, где **ключ это имя поля**, а значение — описание проблемы.
  `Object.values(...).map(item => item.message)` собирает из него список текстов.
- `return` перед `res.status(400)` обязателен: без него код пойдёт дальше и Express
  попробует отправить второй ответ на тот же запрос.
- Последняя строка — всё остальное. Клиенту уходит короткое «Ошибка сервера»,
  без внутренностей: незачем показывать устройство сервера тому, кто будет его ломать.

### Два кода ответа, которые надо различать

| Код | Смысл | Когда |
|---|---|---|
| **400** Bad Request | «виноваты вы, исправьте запрос» | не прошли проверку |
| **500** Internal Server Error | «виноваты мы, сервер сломался» | упала база, ошибка в коде |

Отправлять `500` на неправильные данные клиента — распространённая ошибка новичков.
Фронтендер по `500` не сможет подсветить поле формы красным: он не знает, что чинить.

### Проверяем

Повторите запрос с опечаткой:

```json
{
  "error": "Задача не прошла проверку",
  "problems": ["Поле title обязательно"]
}
```

Статус **400**. Загляните в Atlas: **новой пустой задачи нет.** Дыру закрыли. ✅

Теперь `{ "title": "Помыть посуду", "priority": "ochen srochno" }` → `400`,
`"priority может быть только low, normal или high"`.

И правильный: `{ "title": "Сдать проект", "priority": "high" }` → `201`.

## Часть 6 — Запас: одна задача по `_id` (если осталось время)

Если дошли сюда — открывайте `steps/4-crud.js` и `npm run step4`. Если нет, это первое,
что сделаем во вторник; посмотреть можно дома.

В каждом ответе есть `_id` — 24 символа, MongoDB выдаёт его сама. Это **серийный номер**
задачи: не название (оно может повторяться) и не позиция в списке (список переставили —
позиция уехала), а несмываемая метка именно этого документа. Все операции с **одной**
задачей идут по нему.

```js
app.get('/tasks/:id', async (req, res) => {
  const task = await Task.findById(req.params.id)
  if (!task) return res.status(404).json({ error: 'Задача не найдена' })
  res.json(task)
})

app.patch('/tasks/:id', async (req, res) => {
  const task = await Task.findByIdAndUpdate(req.params.id, req.body, {
    new: true,           // вернуть НОВУЮ версию; без этого придёт старая
    runValidators: true, // проверить правила схемы
  })
  …
})

app.delete('/tasks/:id', async (req, res) => {
  const task = await Task.findByIdAndDelete(req.params.id)
  …
})
```

> 📎 Код выше сокращён: в файле каждый из трёх маршрутов обёрнут в `try/catch`,
> и все они отдают ошибку через одну общую функцию `sendError`. Откройте
> `steps/4-crud.js` целиком — там видно, как это устроено.

**Здесь:** `:id` — кусок адреса, который меняется, его значение лежит в `req.params.id`.
А две настройки у `findByIdAndUpdate` — это ловушка, на которую попадаются все:
**по умолчанию** он возвращает документ **до** изменения и **не проверяет схему** вообще.
Разберём во вторник подробно.

Это **CRUD** — Create, Read, Update, Delete. Четыре действия, из которых состоит любое
приложение с данными.

## Конспект

```js
// 1. Подключение
import 'dotenv/config'
await mongoose.connect(process.env.MONGODB_URI, { serverSelectionTimeoutMS: 5000 })

// 2. Модель без правил — пускает мусор
const Task = mongoose.model('Task', { title: String, isDone: Boolean })

// 3. Схема с правилами — не пускает
const taskSchema = new mongoose.Schema({
  title:    { type: String,  required: [true, 'Поле title обязательно'] },
  isDone:   { type: Boolean, default: false },
  priority: { type: String,  enum: { values: ['low','normal','high'], message: '…' }, default: 'normal' },
})

// 4. Операции
await Task.find()            // все
await Task.create(req.body)  // создать

// 5. Ошибка проверки → 400, а не 500
catch (error) {
  if (error.name === 'ValidationError') { /* 400 + error.errors */ }
}
```
